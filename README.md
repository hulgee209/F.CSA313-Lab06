# Лаборатори №6: Тест тохиолдол боловсруулах — Category-Partition ба PICT

- **Нэр:** Э.Батхүлэг
- **Оюутны код:** B232270040
- **Хичээл:** F.CSA313 — Программ хангамжийн чанарын баталгаа ба тест
- **Он:** 2026

## Зорилго

Энэ лабораторийн зорилго нь Category-Partition аргаар банкны шилжүүлгийн функцийн тестийн сонголт, төлөөлөх утга, хязгаарлалт болон тестийн спецификаци боловсруулах, мөн Microsoft PICT хэрэгслээр 2-way болон 3-way тестийн багц үүсгэж харьцуулах юм.

# A. Category-Partition

## A1. Сонголт ба төлөөлөх утгууд

Шалгах функц:

`POST /transfer`

Оролтын параметрүүд: `from`, `to`, `amount`, `currency`.

| Параметр | Сонголт | Төлөөлөх утга | Тэмдэглэгээ |
|---|---|---|---|
| From | Valid | Байгаа, царцаагаагүй данс | Хэвийн |
| From | Frozen | Байгаа боловч царцаасан данс | [ERROR], [SINGLE] |
| From | Missing | Системд байхгүй данс | [ERROR], [SINGLE] |
| To | Valid | From-оос өөр, байгаа данс | Хэвийн |
| To | Missing | Системд байхгүй данс | [ERROR], [SINGLE] |
| To | SameAsFrom | From-той ижил данс | [ERROR], [SINGLE] |
| Amount | Normal | Тэгээс их, үлдэгдэл болон өдрийн лимитэд багтах дүн | Хэвийн |
| Amount | Zero | Тэг дүн (`amount = 0`) | [ERROR], [SINGLE] |
| Amount | OverBalance | Шилжүүлэгч дансны боломжит үлдэгдлээс их дүн | [ERROR], [SINGLE] |
| Amount | OverLimit | Өдрийн лимитээс их дүн | [ERROR], [SINGLE] |
| Currency | Same | Дансны валюттай ижил валют | Хэвийн |
| Currency | Different | Дансны валютаас өөр валют | Хөрвүүлэлт шаардлагатай |

`[ERROR]` нь алдаа үүсгэх төлөөлөх утгыг заана. `[SINGLE]` нь тухайн алдааны төрлийг бусад алдаанаас тусад нь шалгах тестийн сонголтыг илэрхийлнэ.

Далд орчны нөхцөлүүд:

- From дансны үлдэгдэл.
- Өдрийн лимитийн үлдсэн хэмжээ.
- From болон To дансны валют.
- Валют хөрвүүлэх ханш.

Эдгээр нөхцөл нь Amount-ийн хэвийн, үлдэгдлээс давсан болон лимитээс давсан утгыг тодорхойлоход нөлөөлнө.

## A2. Хязгаарлалт ба тооцоо

### Алдааны давуу эрэмбэ

Нэг хүсэлтэд хэд хэдэн алдаа зэрэг байвал дараах эрэмбээр эхний алдааг хүлээгдэж буй үр дүн гэж үзнэ:

1. `ERROR_NO_FROM`
2. `ERROR_FROZEN`
3. `ERROR_NO_TO`
4. `ERROR_SAME_ACCOUNT`
5. `ERROR_BAD_AMOUNT`
6. `ERROR_INSUFFICIENT`
7. `ERROR_LIMIT`

Энэ эрэмбийг тестийн oracle боловсруулах зорилгоор сонгосон бөгөөд бодит системийн хэрэгжүүлэлтээс баталгаажуулсан дүрэм биш.

### IF хязгаарлалтууд

1. IF From = Missing THEN Amount = Normal.
2. IF To = Missing THEN Amount = Normal.

Эдгээр хязгаарлалт нь From эсвэл To данс байхгүй үед Amount-ийн бусад утгуудыг сонгохоос сэргийлнэ.

### Бүрэн олонлогийн тооцоо

From: 3 сонголт  
To: 3 сонголт  
Amount: 4 сонголт  
Currency: 2 сонголт

Хязгаарлалтгүй бүрэн олонлог:

`N = 3 × 3 × 4 × 2 = 72`

From = Missing үед Amount нь Normal байх ёстой. Иймээс Amount-ийн Normal-оос бусад 3 утгыг хасах хослолын тоо:

`1 × 3 × 3 × 2 = 18`

To = Missing үед Amount нь Normal байх ёстой. Хасах хослолын тоо:

`3 × 1 × 3 × 2 = 18`

Хоёр нөхцөлд давхар хамаарах хослолыг хоёр удаа хассаныг засварлах тоо:

`1 × 1 × 3 × 2 = 6`

Иймээс хоёр IF хязгаарлалтыг хэрэглэсний дараах хослолын тоо:

`M = 72 − 18 − 18 + 6 = 42`

**Үр дүн: 72 → 42.**

Энэ тооцоонд зөвхөн дээрх хоёр IF хязгаарлалтыг тооцсон бөгөөд бусад бизнес дүрмийг оруулаагүй.

## A3. Тестийн спецификаци

| № | From | To | Amount | Currency | Хүлээгдэх үр дүн |
|---:|---|---|---|---|---|
| 1 | Valid | Valid | Normal | Same | HTTP 201, `{"result":"OK"}` |
| 2 | Missing | Valid | Normal | Same | `ERROR_NO_FROM` |
| 3 | Frozen | Valid | Normal | Same | `ERROR_FROZEN` |
| 4 | Valid | Missing | Normal | Same | `ERROR_NO_TO` |
| 5 | Valid | SameAsFrom | Normal | Same | `ERROR_SAME_ACCOUNT` |
| 6 | Valid | Valid | Zero | Same | `ERROR_BAD_AMOUNT` |
| 7 | Valid | Valid | OverBalance | Same | `ERROR_INSUFFICIENT` |
| 8 | Valid | Valid | OverLimit | Same | `ERROR_LIMIT` |
| 9 | Valid | Valid | Normal | Different | HTTP 201, `{"result":"OK"}` |
| 10 | Missing | Missing | Normal | Same | `ERROR_NO_FROM` |

Тестийн setup хийхдээ дансны үлдэгдэл, өдрийн лимит болон валютын нөхцөлийг тодорхой заана. 10-р тест нь давхар алдаатай нөхцөл бөгөөд сонгосон давуу эрэмбийн дагуу `ERROR_NO_FROM` хүлээнэ.

# B. PICT — Pairwise Covering Array

## B1. Browser model

`browser.model` файлын параметрүүд:

- Content: Allow, Restrict, Block
- Cookies: Allow, Restrict, Block
- Popups: Yes, No
- Addons: Yes, No
- Attacks: Yes, No
- Forgeries: Yes, No

Бүрэн олонлогийн хэмжээ:

`3 × 3 × 2 × 2 × 2 × 2 = 144`

PICT-ээр ажиллуулсан үр дүн:

| Хамрах хүрээ | Тестийн мөрийн тоо |
|---|---:|
| 2-way | 10 |
| 3-way | 20 |

PICT-ийн greedy алгоритм нь хамрах ёстой хослолуудыг сонгон тестийн мөр үүсгэдэг. Greedy арга нь хамгийн цөөн боломжит мөрийг заавал гаргах баталгаа биш. 3-way тест нь гурван параметрийн утгуудын бүх гурвалсан хослолыг хамрах зорилготой тул 2-way тестээс олон мөр шаардаж болно.

## B2. Transfer model-уудын харьцуулалт

PICT ашиглан хязгаарлалтгүй, хязгаарлалттай болон сөрөг утгатай гурван загварыг ажиллуулав.

| Загвар | Тестийн мөрийн тоо | Happy path |
|---|---:|---|
| transfer-nc.model | 13 | Байгаа |
| transfer.model | 12 | Байхгүй |
| transfer-neg.model | 16 | 2 мөр |

### Үр дүнгийн тайлбар

`transfer-nc.model` нь 13 тестийн мөр үүсгэсэн. Энэ загварт алдаатай утгуудыг энгийн утга шиг тодорхойлсон тул нэг тестэд хэд хэдэн алдаа зэрэг орж болно. Ийм үед эхний алдаа бусад алдааг далдлах буюу error masking үүсэх эрсдэлтэй.

`transfer.model` нь хоёр IF хязгаарлалттай бөгөөд 12 тестийн мөр үүсгэсэн. Хязгаарлалтгүй загвартай харьцуулахад нэг мөрөөр цөөн байна. Гэхдээ Frozen, SameAsFrom, Zero зэрэг хэд хэдэн алдаатай нөхцөл давхар орсон мөрүүд байгаа тул хүлээгдэх үр дүнг сонгосон давуу эрэмбээр тодорхойлно.

`transfer-neg.model` нь 16 тестийн мөр үүсгэсэн. `~` тэмдэглэгээтэй утгуудыг сөрөг утга гэж тэмдэглэснээр эхний хоёр хэвийн мөрөөс бусад 14 мөр тус бүр нэг сөрөг утгатай болсон. Энэ арга нь нэг алдааг тусад нь шалгах, хүлээгдэх үр дүнг ойлгомжтой болгоход тустай.

### Бодит тест кейсийн спецификаци

Доорх нь PICT-ийн загварын мөрүүдэд тулгуурласан тестийн спецификаци юм. Эдгээрийг бодит API дээр ажиллуулсан гэж үзэхгүй.

#### Тест 1 — Happy path

- **Загварын мөр:** `Valid | Valid | Normal | Same`
- **Setup:** From данс хүчинтэй, царцаагаагүй, үлдэгдэл нь 1000 USD. To данс хүчинтэй бөгөөд From-оос өөр. Өдрийн лимитийн үлдсэн хэмжээ 500 USD.
- **Оролт:**

  `POST /transfer`

  ```json
  {
    "from": "ACC001",
    "to": "ACC002",
    "amount": 100,
    "currency": "USD"
  }
  ```

- **Oracle:** HTTP 201, `{"result":"OK"}`.

#### Тест 2 — Дүн тэг байх

- **Загварын мөр:** `Valid | Valid | ~Zero | Same`
- **Setup:** From болон To данс хүчинтэй, From данс царцаагаагүй, үлдэгдэл 1000 USD, өдрийн лимитийн үлдсэн хэмжээ 500 USD.
- **Оролт:**

  `POST /transfer`

  ```json
  {
    "from": "ACC001",
    "to": "ACC002",
    "amount": 0,
    "currency": "USD"
  }
  ```

- **Oracle:** HTTP 200, `{"result":"ERROR_BAD_AMOUNT"}`.

#### Тест 3 — Шилжүүлэгч данс царцаасан

- **Загварын мөр:** `~Frozen | Valid | Normal | Same`
- **Setup:** From данс царцаасан, To данс хүчинтэй, From дансны үлдэгдэл 1000 USD, өдрийн лимитийн үлдсэн хэмжээ 500 USD.
- **Оролт:**

  `POST /transfer`

  ```json
  {
    "from": "ACC001",
    "to": "ACC002",
    "amount": 100,
    "currency": "USD"
  }
  ```

- **Oracle:** HTTP 200, `{"result":"ERROR_FROZEN"}`.

**Тайлбар:** Дансны ID, үлдэгдэл болон лимитийн тоон утгууд нь жишээ өгөгдөл. Бодит API дээр ажиллуулах үед системийн шаардлага болон тестийн орчинд нийцүүлэн тохируулна.

## B3. Manual болон PICT аргын харьцуулалт, дүгнэлт

1. Manual Category-Partition аргаар тестийн параметр, ангилал, төлөөлөх утга болон хязгаарлалтыг гараар тодорхойлсон.
2. Энэ арга нь тест бүрийн зорилго, хүлээгдэх үр дүн болон алдааны давуу эрэмбийг ойлгомжтой тайлбарлахад тохиромжтой.
3. Гэхдээ параметрийн тоо болон сонголтын тоо нэмэгдэхэд бүх хослолыг гараар боловсруулахад хүндрэлтэй болдог.
4. PICT хэрэгсэл нь параметрийн хослолуудыг автоматаар үүсгэж, 2-way болон 3-way хамрах хүрээг хангах тестийн багц гаргасан.
5. Browser загварын бүрэн олонлог 144 хослолтой байхад PICT-ийн 2-way гаралт 10 мөр, 3-way гаралт 20 мөр байсан.
6. Transfer загваруудын гаралт нь загварын тодорхойлолт болон хязгаарлалтаас хамаарч өөр өөр байв: `transfer-nc.model` 13, `transfer.model` 12, `transfer-neg.model` 16 мөр үүсгэсэн.
7. Хязгаарлалтгүй загварт хэд хэдэн алдаатай нөхцөл нэг мөрөнд давхар орж болох тул хүлээгдэх үр дүнг тодорхойлоход алдааны давуу эрэмбэ хэрэгтэй.
8. Сөрөг утгыг `~` тэмдэглэгээгээр тусгаарлах нь нэг алдааг дангаар нь шалгах тестийн мөрүүдийг гаргахад тусалсан.
9. Manual арга нь бизнес дүрэм болон тестийн зорилгыг тодорхойлоход, харин PICT нь хослолуудыг автоматаар үүсгэхэд давуу талтай.
10. Иймээс хоёр аргыг хослуулан ашиглаж, PICT-ийн үүсгэсэн тестүүдийг шаардлага болон хүлээгдэх үр дүнтэй тулган баталгаажуулах нь үр дүнтэй гэж дүгнэв.
